## ⚡ TL;DR: Золотое правило и готовый рецепт

Чтобы программно вставить текст и отправить сообщение в DeepSeek Web из расширения:
1. **Вставлять текст ТОЛЬКО через дескриптор прототипа `HTMLTextAreaElement.prototype`**:
   ```javascript
   const proto = Object.getOwnPropertyDescriptor(window.HTMLTextAreaElement.prototype, 'value');
   proto.set.call(textarea, text);
   textarea.dispatchEvent(new Event('input', { bubbles: true, composed: true }));
   textarea.dispatchEvent(new Event('change', { bubbles: true, composed: true }));
   ```
2. **ОБЯЗАТЕЛЬНО выдержать паузу 350–400 мс** на reconciliation-цикл React 18 (чтобы кнопка перешла из состояния `disabled` в активное состояние).
3. **Отправлять ТОЛЬКО прямым вызовом React Fiber Handlers (`triggerReactSubmit`)**:
   ```javascript
   const propKey = Object.keys(sendBtn).find(k => k.startsWith('__reactProps$') || k.startsWith('__reactEventHandlers$'));
   if (propKey && typeof sendBtn[propKey]?.onClick === 'function') {
     sendBtn[propKey].onClick({ preventDefault() {}, stopPropagation() {} });
   }
   ```
4. **НЕ ИСПОЛЬЗОВАТЬ** эмуляцию клавиши Enter (`isTrusted: false` блокируется).
5. **НЕ ИСПОЛЬЗОВАТЬ** DOM-клик `sendBtn.click()` (React не слушает нативные клики на этой кнопке).
6. **НЕ ИСПОЛЬЗОВАТЬ** внешний Python-кликер (координаты сбиваются, путает кнопку отправки с кнопками «Умный поиск» и «Глубокое мышление»).
7. **Управлять дедупликацией через мьютекс** с таймаутом не менее 3.5 сек, чтобы исключить повторную отправку.

## 🧠 Анатомия архитектуры чата DeepSeek

1. **Контролируемый ввод React (Controlled Component + `_valueTracker`):**  
   Поле ввода сообщений (`#chat-input` / `textarea`) контролируется внутренним хуком `useState`. React перехватывает геттеры и сеттеры свойства `.value` на элементе и кеширует его в `textarea._valueTracker`. Если просто присвоить `textarea.value = 'текст'`, трекер React видит несоответствие, сбрасывает значение обратно в пустое или не триггерит обновление `state`.

2. **Защита `event.isTrusted` на событиях клавиатуры:**  
   Слушатели `keydown` на контейнере формы проверяют флаг `event.isTrusted`. Любое событие, созданное через `new KeyboardEvent('keydown', { key: 'Enter' })`, имеет `isTrusted === false` и безусловно отбрасывается DeepSeek.

3. **Синтетическая диспетчеризация React Fiber:**  
   Обработчик клика на кнопке со стрелкой (отправка) не висит в нативном `addEventListener('click')`. Он зарегистрирован в дереве компонентов React Fiber под внутренним ключом экземпляра вида `__reactProps$[randomId]` или `__reactEventHandlers$[randomId]`.

4. **Асинхронный цикл рендеринга кнопки:**  
   После изменения значения в `textarea` кнопка отправки остаётся неактивной (серой, с CSS-классом блокировки и отсутствием обработчика) в течение **~150–300 мс**, пока React производит вычисление состояния валидности ввода.

## 📜 Хроника 18 попыток: почему они провалились

### Попытки 1–3: Наивная вставка через DOM
* **Что делалось:**  
  `textarea.value = text;`  
  `textarea.dispatchEvent(new Event('input'));`
* **Симптомы:**  
  Текст визуально появлялся в поле ввода. Однако кнопка отправки (синяя стрелка вверх) оставалась серой и заблокированной. При попытке нажать Enter или кнопку вручную — форма считала поле абсолютно пустым.
* **Причина провала:**  
  React `_valueTracker` перехватывает обращение к нативному полю. Прямое присвоение не обновляет внутренний стейт React. Как только компонент перерендеривался (например, при потере фокуса), введённый текст мгновенно стирался.

---

### Попытки 4–6: Нативный сеттер прототипа + синтетический Enter
* **Что делалось:**  
  Использован сеттер прототипа:  
  `Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set.call(textarea, text);`  
  Затем отправлялись события `KeyboardEvent`:  
  `textarea.dispatchEvent(new KeyboardEvent('keydown', { key: 'Enter', code: 'Enter', keyCode: 13, which: 13, bubbles: true }));`
* **Симптомы:**  
  Текст успешно зафиксировался в React (кнопка стала синей!). Но событие Enter полностью игнорировалось — сообщение не отправлялось, курсор просто оставался в поле либо переносил строку (`Shift+Enter` поведение).
* **Причина провала:**  
  1. В браузерах свойство `event.isTrusted` доступно только для чтения (`read-only`) и выставляется движком Chromium в `true` **только при реальном физическом нажатии клавиши пользователем**.
  2. Обработчик DeepSeek проверяет `event.isTrusted === true`. Все синтетические нажатия игнорируются для предотвращения спама.

---

### Попытки 7–9: Клик по кнопке отправки через DOM `button.click()`
* **Что делалось:**  
  Находили кнопку отправки через селекторы (`button[type="submit"]`, `div[class*="send"]`, `svg[class*="arrow"]`) и вызывали:  
  `sendButton.click();` или `sendButton.dispatchEvent(new MouseEvent('click', { bubbles: true }));`
* **Симптомы:**  
  Метод `.click()` выполнялся без ошибок в консоли, но сообщение не отправлялось. Кнопка не реагировала.
* **Причина провала:**  
  Кнопка отправки в разметке DeepSeek часто представляет собой `div` или стилизованный `button`, внутри которого лежит SVG-иконка. Нативный обработчик `onclick` отсутствует. Клик слушает React-делегатор на корневом контейнере через SyntheticEvent. Нативные вызовы `element.click()` часто попадали по внутреннему SVG или промахивались мимо React-делегатора.

---

### Попытки 10–12: Ловушка опережения рендера (Race Condition)
* **Что делалось:**  
  Сразу после вызова нативного сеттера текста мгновенно (через 0–50 мс) вызывался клик по кнопке отправки.
* **Симптомы:**  
  Иногда происходил щелчок (анимация клика), но сообщение не уходило. Либо отправлялось пустое сообщение, вызывая ошибку DeepSeek.
* **Причина провала:**  
  После отправки события `input` React 18 ставит задачу обновления состояния в очередь микротасок. Пока стейт не обновился, компонент кнопки отправки в React Fiber остаётся в состоянии `disabled: true`. Вызов обработчика в этот момент попадает в защитную проверку `if (disabled) return;` внутри замыкания компонента кнопки.
* **Открытие:**  
  Необходима задержка минимум **350–400 мс** между вставкой текста и вызовом метода отправки.

### Попытки 13–15: Внешний Python-бот, CDP и OCR-поиск кнопок
* **Что делалось:**  
  Попытка обойти браузерные ограничения с помощью внешнего Python-скрипта через:
  - Эмуляцию мыши (PyAutoGUI / CDP `Input.dispatchMouseEvent`)
  - Распознавание кнопки отправки через OCR (Tesseract / EasyOCR) и поиск по шаблону изображения.
* **Симптомы:**  
  - Бот нажимал на кнопку «Умный поиск» или «Глубокое мышление» вместо кнопки отправки (потому что они расположены рядом под полем ввода и имеют схожие цветовые маркеры).
  - При масштабировании экрана (DPI 125%, 150%) или изменении ширины окна координаты съезжали.
  - Появлялся громкий системный звук клика до того, как текст успевал полностью вставиться.
* **Причина провала:**  
  Визуальные методы поиска кнопок (OCR/CV) крайне нестабильны в динамическом интерфейсе чата. Внешний процесс не синхронизирован с внутренним циклом событий браузера.

### Попытки 16–17: Проблема двойной отправки, каскадных методов и «громкий клик» со звуком
* **Что делалось:**  
  Попытка сделать отказоустойчивую отправку: сначала тихий метод через React, а при неудаче — резервный аппаратный метод со звуковым подтверждением и визуальной анимацией клика.
* **Симптомы:**  
  Пользователь заметил: «*теперь срабатывает дважды что ли? вроде что-то отправляется, потом опять вставляется текст в поле, но жмётся на кнопку с кликом громким слишком рано, когда текст ещё не вставился полностью*».
* **Как именно был реализован громкий звук клика?**  
  Это был не системный звук ОС и не питоновский бип. В плагин (`src/main-world.js`) был встроен собственный программный синтезатор звука на **Web Audio API (`window.AudioContext`)**:
  - **Обход Autoplay Policy браузера:** Chromium запрещает воспроизведение звука без жеста пользователя. Для обхода мы перехватывали первое касание страницы (`pointerdown`, `keydown`, `click`) и разблокировали контекст (`audioContextInstance.resume()`).
  - **Двухслойный акустический синтез:**
    1. *Верхний щелчок контакта:* генератор синусоиды (`sine`) с быстрым спадом частоты от **1400 Гц до 280 Гц** за 50 мс с экспоненциальным затуханием громкости.
    2. *Механический тактильный импульс:* генератор треугольной волны (`triangle`) со спадом частоты от **360 Гц до 70 Гц** за 40 мс.
    В сумме они давали абсолютно реалистичный, звонкий звук физического щелчка дорогой механической мыши.
* **Почему клик срабатывал второй раз и именно со звуком?**  
  В коде отправки было написано:
  ```javascript
  // Метод 1: Нативный React Fiber Submit (ТИХО)
  const reactSuccess = triggerReactSubmit(inputEl);
  if (reactSuccess) { return; }

  // Метод 2: Резервная отправка (СО ЗВУКОМ)
  playClickSound();
  showClickVisualEffect(coords.x, coords.y);
  clickSendButtonSafely(sendBtn);
  ```
  **Корень бага:** в Метод 1 передавался `inputEl` (элемент `textarea`!), а у поля ввода в React Fiber нет обработчика `onClick` (он есть только у кнопки со стрелкой `sendBtn`). В итоге `triggerReactSubmit(inputEl)` всегда возвращал `false`!  
  Код считал, что Метод 1 не сработал, и **всегда проваливался во второй метод**, воспроизводя громкий звук `playClickSound()` и запуская клик по координатам через CDP и React-кнопку одновременно.
* **Открытие и исправление:**  
  1. Вызывать `triggerReactSubmit` нужно **сразу на `sendBtn`**, а не на `inputEl`.
  2. Громкий звук и параллельный CDP-фоллбек были полностью отключены: отправка стала мгновенной, полностью тихой и однократной.
  3. Введён централизованный мьютекс `isSubmittingCleanly = true` с кулдауном **3.5 секунды**, исключающий повторные параллельные вызовы.

### Попытка 18: Подмена и потеря вызовов инструментов в истории
* **Что делалось:**  
  Инструмент выполнялся (например, `withdraw_listing`), но в рантайме происходило одно из двух:
  1. Повторный вызов инструмента (`preview_listing`, `get_room_history`) терялся — плагин не реагировал.
  2. Происходила подмена: вместо `withdraw_listing` отправлялся `search_listings`.
* **Причина провала:**  
  1. **Подмена:** В функции `getLastAssistantMessageText()` при задержке первого фрагмента SSE буфер был пуст, и срабатывал аварийный поиск по `document.body.innerText` с глубиной 6 сообщений назад. Сканер находил в истории чата старый вызов `<search_listings>` и перезапускал его вместо текущего `<withdraw_listing>`.
  2. **Потеря повторов:** Переменная сигнатуры `lastProcessedToolCallSignature` сохраняла аргументы вызова и блокировала повторный вызов с теми же параметрами, считая его бесконечным циклом.
* **Открытие:**  
  - Сканировать **строго последнее сообщение** ассистента в DOM, исключая контейнеры, к которым уже прикреплена карточка результата (`.ds-mcp-inline-card`).
  - Сигнатуру дедупликации `lastProcessedToolCallSignature` **обязательно сбрасывать** в начале каждого нового входящего потока и при отправке каждого продолжения.

## 🏆 Итоговое решение: Каноническая архитектура плагина

В версии **v0.4.23+** реализован выверенный конвейер из 4 шагов, работающий со 100% надёжностью:

```
[1. MCP Tool Result Ready]
           │
           ▼
[2. Set Text via Native Prototype Descriptor]
           │ (Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype, 'value').set)
           ▼
[3. Dispatch bubbles & composed input/change events]
           │
           ▼
[4. Sleep 380ms (React 18 State Reconcile)]
           │
           ▼
[5. triggerReactSubmit() via React Fiber Props]
           │ (__reactProps$ / __reactEventHandlers$ .onClick)
           ▼
[6. Reset deduplication signature & engage 3.5s Mutex Lock]
```

### Полный эталонный код функции отправки (`src/main-world.js`):

```javascript
let isSubmittingCleanly = false;

async function submitContinuationCleanly(userText) {
  if (isSubmittingCleanly) {
    emitLog('warn', 'Отправка уже выполняется (мьютекс заблокирован), повторный вызов пропущен.');
    return;
  }
  isSubmittingCleanly = true;

  try {
    // 1. Поиск поля ввода
    const textarea = document.querySelector('textarea#chat-input') ||
                     document.querySelector('textarea[placeholder*="DeepSeek"]') ||
                     document.querySelector('textarea');
    if (!textarea) {
      throw new Error('Поле ввода DeepSeek (#chat-input) не найдено');
    }

    // 2. Вставка текста через нативный прототип (обход _valueTracker в React)
    const nativeSetter = Object.getOwnPropertyDescriptor(window.HTMLTextAreaElement.prototype, 'value')?.set;
    if (nativeSetter) {
      nativeSetter.call(textarea, userText);
    } else {
      textarea.value = userText;
    }

    // 3. Уведомление React о модификации поля
    textarea.dispatchEvent(new Event('input', { bubbles: true, composed: true }));
    textarea.dispatchEvent(new Event('change', { bubbles: true, composed: true }));

    // 4. КРИТИЧЕСКАЯ ПАУЗА: даём React 18 пересчитать стейт и активировать кнопку
    await new Promise(resolve => setTimeout(resolve, 380));

    // 5. Поиск кнопки отправки
    const sendBtn = findSendButton(textarea);
    if (!sendBtn) {
      throw new Error('Кнопка отправки не найдена');
    }

    // 6. Прямой вызов обработчика через внутренний React Fiber
    const reacted = triggerReactSubmit(sendBtn);
    if (!reacted) {
      // Запасной нативный клик, если Fiber-пропсы изменили имя
      sendBtn.click();
    }

    // 7. Сброс сигнатуры дедупликации, чтобы следующий шаг инструмента не заблокировался
    lastProcessedToolCallSignature = '';
    emitLog('info', 'Продолжение инструмента успешно отправлено в DeepSeek.');
  } finally {
    // Разблокировка мьютекса через 3.5 секунды
    setTimeout(() => {
      isSubmittingCleanly = false;
    }, 3500);
  }
}

function triggerReactSubmit(btn) {
  if (!btn) return false;
  try {
    // Поиск React Fiber свойств (__reactProps$xxxx или __reactEventHandlers$xxxx)
    const propKey = Object.keys(btn).find(k => k.startsWith('__reactProps$') || k.startsWith('__reactEventHandlers$'));
    if (propKey && btn[propKey]) {
      const p = btn[propKey];
      if (typeof p.onClick === 'function') {
        p.onClick({ preventDefault() {}, stopPropagation() {} });
        return true;
      }
    }
  } catch (err) {
    console.warn('[MCP] Ошибка вызова Fiber onClick:', err);
  }
  return false;
}
```

## 🚫 Памятка для AI-агентов: Что категорически ЗАПРЕЩЕНО менять

Если вам поручено доработать или отрефакторить расширение DeepSeek MCP Lite:

1. ❌ **НИКОГДА не заменяйте сеттер прототипа на `textarea.value = text`** — это немедленно сломает регистрацию ввода в React.
2. ❌ **НИКОГДА не удаляйте паузу 350–400 мс перед отправкой** — без неё отправка будет происходить по заблокированной кнопке (race condition).
3. ❌ **НИКОГДА не пытайтесь эмулировать Enter через `KeyboardEvent`** — Chromium выставит `isTrusted: false`, и DeepSeek проигнорирует нажатие.
4. ❌ **НИКОГДА не возвращайте сканирование `document.body` или глубину истории на 6 сообщений назад** в `getLastAssistantMessageText()` — это вернёт баг подмены результатов инструментов.
