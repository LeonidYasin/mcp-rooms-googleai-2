# Анализ готовности к Production и Дорожная карта (Roadmap)

В этом документе содержится текущая оценка готовности проекта **MCP Rooms Marketplace (`LeonidYasin/mcp-rooms-googleai-2`)** к боевой (промышленной) эксплуатации, а также приоритезированный план архитектурных и функциональных улучшений для AI-сессий.

---

## 🚦 Готовность проекта к боевой эксплуатации (Production Readiness)

На данный момент проект находится в статусе **функционального прототипа (Proof of Concept)**. Он отлично подходит для демонстрации возможностей MCP, интеграции Gemini Embeddings и реактивных комнат, но **НЕ готов к боевой эксплуатации**.

### ❌ Критические блокеры для вывода в Production:

1. **Отсутствие персистентного хранилища изображений (`/uploads`):**
   - В форме создания объявления фотографии выбираются локально и показываются только в предпросмотре браузера. На сервер они не загружаются и в карточке не сохраняются (`photos: []`).
2. **Утечка API-токенов в URL для SSE комнат:**
   - Подключение к SSE-потоку комнат (`GET /api/rooms/:id/stream`) передает ключ через query-параметр (`?access_token=...`), так как нативный `EventSource` не поддерживает заголовки. Токены оседают в access-логах прокси-серверов и истории браузера.
3. **In-Memory Rate Limiting:**
   - Счетчики запросов хранятся в памяти Node.js. При перезапуске сервиса или при масштабировании на несколько инстансов лимиты сбрасываются.
4. **Демо-режим авто-переговоров (`negotiate_agreement`):**
   - Инструмент агентов `negotiate_agreement` работает в режиме эмуляции (`status: demo_preview`). Он генерирует пример диалога, но не создает реальную комнату и не фиксирует сделки в БД.
5. **Отсутствие Replay в SSE (`Last-Event-ID`):**
   - Поток SSE не обрабатывает заголовок `Last-Event-ID`. При временном сбое сети пропущенные сообщения теряются.
6. **Безопасность и проверка прав владения (Ownership Check):**
   - Нет проверки прав при попытке изменения или удаления уже существующих объявлений.
   - Отсутствует строгий `Content-Security-Policy` для клиентских скриптов.

## 💡 Дорожная карта улучшений (Roadmap)

### 🔴 Приоритет 1: Критическая инфраструктура и безопасность (P1 — Production Blockers)

- [x] **1.1 Персистентная загрузка и хранение фото (`/uploads`)** — ✅ **Issue #16 / PR #16 (merged)**
  - Загрузка файлов на сервер с проверкой типов и ограничением размера до 5 МБ.
  - Сохранение путей к файлам в карточках объявлений и раздача через Express static.
  - *Затронутые файлы:* `server/uploads.ts`, `server.ts`.

- [x] **1.2 Безопасная авторизация SSE (Ticket-based SSE Auth)** — ✅ **Issue #25 / PR #25 (merged)**
  - Внедрение механизма одноразовых короткоживущих тикетов (`POST /api/rooms/:id/ticket`).
  - Проверка тикета `?ticket=...` в SSE-стриме вместо передачи сырых Bearer токенов.
  - *Затронутые файлы:* `server/auth.ts`, `server.ts`, `tests/sse-ticket-auth.test.ts`.

- [x] **1.3 Персистентный Rate Limiting & Trust Proxy** — ✅ **Issue #14 / PR #14 (merged)**
  - Хранение счетчиков в SQLite (`rate_limit_hits`) с поддержкой `X-Forwarded-For`.
  - Защита от превышения лимитов с HTTP 429 и заголовком `Retry-After`.
  - *Затронутые файлы:* `server/http-guard.ts`.

- [x] **1.4 Поддержка `Last-Event-ID` в SSE** — ✅ **Issue #31 / PR #31 (merged)**
  - Фильтрация и доотправка пропущенных сообщений комнат по заголовочному или query параметру `Last-Event-ID`.
  - *Затронутые файлы:* `server.ts`, `tests/sse-replay.test.ts`.
