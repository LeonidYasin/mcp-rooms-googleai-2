# Скилл AI-Агента: Правила и протокол работы с репозиторием (Repository Rules Skill)

Этот документ представляет собой формализованное руководство (Skill Prompt) для автономных AI-агентов (Jules, Gemini и др.), работающих над проектом **MCP Rooms Marketplace (`LeonidYasin/mcp-rooms-googleai-2`)**.

---

## 🎯 Назначение Скилла

Гарантировать безопасное параллельное развитие проекта несколькими независимыми сессиями AI-агентов без прямых конфликтов в веточках, с сохранением высокой степени покрытия тестами и полной прозрачностью статуса задач.

---

## 📜 Обязательный протокол работы агента (Agent Workflow)

### 1. Этап исследования и захвата задачи (Task Claiming)
- **Изучение состояния:** перед началом работы прочтите `docs/session_coordination.md` и `docs/roadmap.md`.
- **Анализ пересечения файлов (File Impact Analysis):** убедитесь, что планируемые к изменению файлы не находятся в процессе редактирования другой активной сессией.
- **Захват задачи:**
  1. Измените статус задачи в `docs/session_coordination.md` и `docs/roadmap.md` с `⏳ Бэклог` на `🔄 В разработке`.
  2. Укажите имя сессии, создаваемую ветку (`feat/<task-name>` или `fix/<description>`) и текущее время UTC.
  3. Отправьте коммит изменения координационного файла в `main`.

### 2. Этап разработки и тестирования (Development & Testing)
- **Создание ветки:** работайте строго в отдельной ветке. Никогда не коммитьте напрямую в `main`.
- **Обязательное тестирование:**
  ```bash
  npm test
  ```
  Все существующие и новые тесты должны проходить на 100%. При добавлении эндпоинтов или логики добавляйте новые модульные/интеграционные тесты в папку `tests/`.

### 3. Этап создания и оформления PR (PR Reporting Standard)
- Для создания и слияния PR используйте скрипт `scripts/github_mcp_cli.py` или GitHub REST API.
- **Требование к полной отчётности:** тело PR и запись в `Handover Log` должны содержать:
  - 📌 **Номер PR и ссылка.**
  - 🚦 **Статус:** `Draft`, `Open`, `Merged` или `Blocked`.
  - 🎯 **Выполненные изменения:** подробный список реализованных функций и модифицированных файлов.
  - ⏳ **Оставшиеся TODO:** нереализованные нюансы или edge cases.
  - 🧪 **Результаты тестов:** статус выполнения `npm test`.

### 4. Этап завершения и освобождения задачи
- После успешного слияния PR в ветку `main`:
  1. Отметьте статус задачи как `✅ Завершено` в `docs/session_coordination.md` и `docs/roadmap.md` с указанием номера PR.
  2. Заполните журнал передаточного контекста (Handover Log) для следующих сессий.
